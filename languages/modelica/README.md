# @modelscript/modelica

Flagship Modelica 3.x physical modeling and simulation compiler (`.mo`) for ModelScript. Features a custom WebAssembly GLR incremental parser, high-performance AssemblyScript flattening kernel, direct DAE arena lowering, port balancing, unit verification, 70+ compiler lint rules (`M1xxx`–`M6xxx`), and bidirectional Triple Graph Grammar (TGG) rules for cross-domain synchronization.

---

## Core Capabilities

- **WASM GLR Incremental Parser**: Generated by `@modelscript/dsl` (`buildParser`), compiling directly to native WebAssembly (`parser.wasm`) for microsecond incremental parsing and syntax error recovery.
- **Arena-Native Flattening Pipeline**: Implements `ModelicaFlattener` coordinated with an in-WASM AssemblyScript kernel (`assembly/flattener.ts`) supporting `hybrid`, `wasm`, `ts`, and `diff` execution modes.
- **Data-Oriented DAE Lowering**: Direct lowering of equations, algorithms, and expressions into linear memory `DAEBuilder` integer IDs (`ExprId`, `EqId`, `StmtId`) with zero intermediate AST wrapper allocations.
- **Connection Balancing & Flow Variables**: Rigorous topological port balancing via `ModelicaPortBalancer` supporting standard and expandable connectors.
- **Unit & Dimensional Checking**: Physical dimension inference and unit consistency verification across equations and component connections.
- **Salsa Query Engine Integration**: Demand-driven memoization of class instantiation, type resolution, variability, causality, and effective modifications.
- **Polyglot TGG Rules**: Declarative Triple Graph Grammar rules enabling bidirectional synchronization with SysML v2 blocks, OWL 2 ontological classes, and CSV telemetry datasets.
- **Compiler Lints**: Over 70+ static and semantic diagnostic rules aligned with OpenModelica error codes (`M1xxx` through `M6xxx`).

## Semantic / Compiler Lint Rules (`M1xxx`–`M6xxx`)

| Range / Code | Rule / Category              | Severity            | Description                                                                           |
| :----------- | :--------------------------- | :------------------ | :------------------------------------------------------------------------------------ |
| `M1001`      | `parse-error`                | `error`             | Syntax errors detected by the native WebAssembly GLR parser.                          |
| `M1002`      | `parse-missing`              | `error`             | Expected token missing in Modelica declaration, equation, or statement.               |
| `M1003`      | `empty-array-constructor`    | `error`             | Empty array constructor `[]` or `{}` is not valid in Modelica.                        |
| `M2001`      | `duplicate-element`          | `error`             | Element already declared in the current class or component scope.                     |
| `M2002`      | `variable-not-found`         | `error`             | Variable or component reference not found in scope.                                   |
| `M2003`      | `class-not-found`            | `error`             | Type or class specifier not found in scope.                                           |
| `M2004`      | `modifier-not-found`         | `error`             | Modified element not found in target class hierarchy.                                 |
| `M2005`      | `identifier-mismatch`        | `error`             | Class begin and `end` identifiers do not match.                                       |
| `M3001`      | `type-mismatch-binding`      | `error`             | Type mismatch in variable binding expression.                                         |
| `M3002`      | `type-mismatch-modifier`     | `error`             | Type mismatch in component or class modifier expression.                              |
| `M3003`      | `not-plug-compatible`        | `error`             | Connectors in `connect(...)` clause are not plug-compatible.                          |
| `M3004`      | `not-a-connector`            | `error`             | Referenced element in `connect(...)` clause is not a `connector`.                     |
| `M3006`      | `function-arg-type-mismatch` | `error`             | Function call argument type does not match formal parameter type.                     |
| `M4001`      | `extends-cycle`              | `error`             | Circular `extends` inheritance chain detected.                                        |
| `M4002`      | `duplicate-modification`     | `error`             | Same element modified multiple times in a modification clause.                        |
| `M4005`      | `protected-modification`     | `error`             | Protected element modified from outside its enclosing class.                          |
| `M5001`      | `equation-type-mismatch`     | `error`             | Left-hand and right-hand sides of an equation have incompatible types or dimensions.  |
| `M6xxx`      | `synchronous-clocks`         | `error` / `warning` | Synchronous clock partitioning, sub-sampling/super-sampling, and state machine rules. |

## Architecture: Arena-Native Flattening, Multi-File Indexing & Extensions

- **Arena-Native `ModelicaFlattener` (`hybrid` | `wasm` | `ts` | `diff`)**: Equations, algorithm statements, and expressions are lowered directly from linear WebAssembly CST pointers into `DAEBuilder` struct-of-arrays tables without intermediate AST wrapper allocations. Combined with `@modelscript/runtime`, the pipeline performs constant folding (`foldArenaConstants`), alias elimination (`eliminateArenaAliases`), Pantelides index reduction, and Tarjan Block Lower Triangular (BLT) sorting.
- **Multi-File `WorkspaceIndex` & Package Resolution**: Cross-file `within` clauses, `package.mo` / `package.order` hierarchies, and the full Modelica Standard Library (MSL) are unified into a workspace-wide symbol index with incremental Salsa dependency invalidation.
- **Embedded CSG, FEA & CFD Extensions**: Supports native `shape` classes and constructive solid geometry (`src/extensions/csg.ts`, `shape-flattener.ts`), automated 3D multibody mass/inertia tensor synthesis (`multibody-generator.ts`), and embedded continuum FEA/CFD study definitions (`study-flattener.ts`, `studies.ts`) bridged to STEP B-Rep CAD and CAE solvers.

## CLI Usage (`msx`)

```bash
# Flatten a Modelica model to flat DAE representation
msx flatten BouncingBall BouncingBall.mo

# Lint a Modelica file or package directory
msx lint BouncingBall.mo

# Simulate a Modelica model and export trajectory results
msx simulate BouncingBall BouncingBall.mo --stop-time=5.0

# Render schematic diagram or component icon to SVG
msx render BouncingBall BouncingBall.mo --out=diagram.svg
```

## Programmatic Usage

```typescript
import { Context } from "@modelscript/modelica/context";
import { createWasmParser } from "@modelscript/modelica/parser";

// 1. Initialize WASM GLR parser
const modelicaWasmPath = require.resolve("@modelscript/modelica/parser.wasm");
const { parser } = await createWasmParser(modelicaWasmPath);
Context.registerParser(".mo", parser);

// 2. Load and flatten a model
const context = new Context();
context.loadFile("file:///path/to/BouncingBall.mo", sourceCode);

// 3. Flatten directly into linear-memory DAEBuilder
const dae = context.flattenArena("BouncingBall");
```
