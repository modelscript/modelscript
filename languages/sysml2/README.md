# @modelscript/sysml2

Systems Modeling Language v2 (SysML v2) and Kernel Modeling Language (KerML) compiler (`.sysml`, `.kerml`, `.sysmlx`), AST querying, formal SMT/state-machine/activity verification, 45-rule diagnostic linter (`1001`–`5016`), and cross-domain transformation engine for ModelScript.

---

## Core Capabilities

- **Native WebAssembly GLR Incremental Parser**: Generated by `@modelscript/dsl` (`buildParser`), compiling directly into high-throughput WASM (`parser.wasm`) for microsecond parsing and incremental syntax tree recovery.
- **KerML & SysML v2 Standard Library**: Embedded snapshots of the KerML and SysML v2 standard libraries (`loadEmbeddedKerMLStdlib`) for full symbol resolution, type hierarchy deduction, and dimensional quantities (`ISQ`).
- **Systems Architecture & Decomposition**: Full query support for part definitions, item definitions, ports, connection definitions, allocations, and parametric constraints.
- **Behavioral Modeling & Formal Verification**: State machine determinism/deadlock verification (`state-machine-verifier.ts`), activity control-flow & soundness analysis (`activity-cfa.ts`, `activity-soundness.ts`, `activity-verifier.ts`), decision table exhaustiveness/disjointness verification (`decision-table-verifier.ts`), contract verification (`contract-verifier.ts`), and SMT / reasoner bridges (`smt-bridge.ts`, `reasoner-bridge.ts`, `nra-solver.ts`).
- **Standard Model Interchange & Enterprise Coexistence**: Lossless OMG JSON-LD `.sysmlx` interchange (`sysmlx-interchange.ts`), SSP/FMU container export (`sysml2-container-exporter.ts`), and Cameo Teamwork Cloud (TWC) / OpenMBEE MMS synchronization (`enterprise-sync-gateway.ts`).
- **Bidirectional Polyglot TGG Rules**: AOT-compiled Triple Graph Grammar rules for bidirectional co-evolution across domains:
  - **SysML v2 ↔ Modelica**: Map part definitions to Modelica components and attributes to physics parameters (`SysML2ToModelica`).
  - **SysML v2 ↔ OWL 2**: Map taxonomies and concepts to ontology subclasses, individuals, and object properties (`SysML2ToOWL2SubClassOf`, `SysML2ToOWL2ObjectProperty`, etc.).
  - **SysML v2 ↔ STEP CAD**: Map physical parts to CAD geometry, dimensional measures, and spatial coordinate placements (`SysML2ToStepProduct`, `SysML2ToStepMeasure`, `SysML2ToStepPlacement`).
- **Visual Diagram Synthesis**: Automatic layout generation for block definition diagrams (BDD), internal block diagrams (IBD), and state transition charts (`src/diagram/`).

## Semantic / Pre-Flight Lint Rules (`SysML2ErrorCode`, `1001`–`5016`)

| Code   | Rule                                 | Severity  | Description                                                                                            |
| :----- | :----------------------------------- | :-------- | :----------------------------------------------------------------------------------------------------- |
| `1001` | `parse-error`                        | `error`   | Syntax error detected by the native WebAssembly GLR parser.                                            |
| `1002` | `parse-missing`                      | `error`   | Expected token missing in SysML v2 / KerML construct.                                                  |
| `1003` | `definition-naming`                  | `warning` | Definition identifier should start with an uppercase letter (`PascalCase`).                            |
| `1004` | `usage-naming`                       | `warning` | Usage identifier should start with a lowercase letter (`camelCase`).                                   |
| `1005` | `package-naming`                     | `warning` | Package identifier should start with an uppercase letter.                                              |
| `2001` | `duplicate-member`                   | `warning` | Duplicate member name declared within the same namespace or definition scope.                          |
| `2002` | `symbol-not-found`                   | `error`   | Referenced symbol could not be resolved in lexical scope or imported packages.                         |
| `2003` | `unresolved-target`                  | `error`   | Allocation target (`allocate ... to target`) could not be resolved.                                    |
| `2004` | `unresolved-source`                  | `error`   | Allocation source (`allocate source to ...`) could not be resolved.                                    |
| `2005` | `unresolved-import`                  | `error`   | Imported package or member path could not be resolved in workspace or standard library.                |
| `2006` | `unresolved-transition-state`        | `error`   | State machine transition source or target state could not be resolved in the enclosing state machine.  |
| `3001` | `type-mismatch`                      | `error`   | Cannot assign value of incompatible actual type to feature with declared type.                         |
| `3002` | `incompatible-port-connection`       | `error`   | Connection links two ports with incompatible port definitions or conjugated item flows.                |
| `3003` | `dimensional-mismatch`               | `error`   | Physical unit or ISQ dimension of expression does not match the feature's declared dimension.          |
| `3004` | `invalid-multiplicity-bounds`        | `error`   | Multiplicity lower bound is strictly greater than upper bound (`[lower..upper]`).                      |
| `3005` | `target-not-requirement`             | `error`   | Target of a `satisfy` relationship is not a `requirement def` or `requirement` usage.                  |
| `3006` | `verify-target-not-a-requirement`    | `error`   | Target of a `verify` statement inside a verification case is not a Requirement.                        |
| `3007` | `dimensional-connection-mismatch`    | `error`   | Connected endpoints have incompatible physical dimensions.                                             |
| `4001` | `circular-specialization`            | `error`   | Definition or usage transitively specializes (`:>`) itself.                                            |
| `4002` | `circular-satisfaction`              | `error`   | Requirement satisfaction graph contains a cycle.                                                       |
| `4003` | `empty-definition`                   | `info`    | Definition has no declared members or features.                                                        |
| `4004` | `abstract-requirement-violation`     | `error`   | Concrete requirement refinement violates abstract requirement constraints.                             |
| `4005` | `ontological-inconsistency`          | `error`   | OWL 2 / DL reasoner detected an ontological inconsistency in specialization or disjointness axioms.    |
| `4006` | `missing-subject`                    | `info`    | Requirement definition or usage has no specified `subject` or `satisfy` relationship.                  |
| `4007` | `empty-package`                      | `info`    | Package contains no member declarations.                                                               |
| `4008` | `requirement-without-constraint`     | `info`    | Requirement has neither `require constraint` expressions nor `doc` specification text.                 |
| `4009` | `empty-verification-case`            | `info`    | `verification def` / `verification` case has no `verify` objective or sub-actions.                     |
| `4010` | `missing-verification-objective`     | `warning` | Verification case lacks an `objective` block or `verify` statement.                                    |
| `4011` | `unverified-requirement`             | `warning` | Requirement is not verified by any verification case in the enclosing package.                         |
| `5001` | `constraint-violated`                | `error`   | Parametric `assert constraint` evaluates to `false` under current parameter bindings.                  |
| `5002` | `requirement-failed`                 | `error`   | Requirement `require constraint` evaluates to `false`.                                                 |
| `5003` | `broken-interface-contract`          | `error`   | Component or port assume-guarantee contract is violated across a connection boundary.                  |
| `5004` | `activity-cfa-unreachable`           | `warning` | Unreachable action node detected in activity control-flow graph.                                       |
| `5005` | `activity-soundness-violation`       | `error`   | Activity workflow net violates soundness (deadlock, lack of synchronization, or improper termination). |
| `5006` | `definite-assignment-violation`      | `error`   | Action variable or output parameter may be read before definite assignment along a control-flow path.  |
| `5007` | `statemachine-nondeterministic`      | `error`   | Outgoing transitions from the same state have overlapping (non-disjoint) guard conditions.             |
| `5008` | `statemachine-deadlock`              | `error`   | Outgoing transition guards from a state are non-exhaustive, leaving a deadlock gap.                    |
| `5009` | `satisfying-violated-requirement`    | `error`   | Part claims to `satisfy` a requirement whose mathematical constraints it violates.                     |
| `5010` | `conflicting-requirements`           | `error`   | Set of requirements in package is mutually unsatisfiable (UNSAT core witness generated).               |
| `5011` | `interprocedural-contract-violation` | `error`   | Callee precondition or caller postcondition contract violated across action/calc invocation.           |
| `5012` | `loop-non-terminating`               | `warning` | Activity or action loop variant cannot be proven to strictly decrease toward termination.              |
| `5013` | `decision-table-non-exhaustive`      | `warning` | Decision node (`decide`) branch guards do not cover all possible input domain valuations.              |
| `5014` | `decision-table-nondeterministic`    | `error`   | Decision node (`decide`) has overlapping branch guards that can fire simultaneously.                   |
| `5015` | `decision-table-dead-branch`         | `warning` | Decision node (`decide`) contains a branch guard that is logically unsatisfiable or shadowed.          |
| `5016` | `activity-safety-violation`          | `error`   | Activity execution trace violates a temporal or invariant safety property.                             |

## CLI Usage (`msx sysml`)

```bash
# Validate SysML v2 / KerML models against all 1001–5016 semantic & formal rules
msx sysml check Spacecraft.sysml

# Inspect package hierarchy, parts, ports, requirements, and state machines
msx sysml info Spacecraft.sysml

# Export to OMG JSON-LD interchange (.sysmlx), SSP container (.ssp), or FMI 3.0 FMU (.fmu)
msx sysml export Spacecraft.sysml --format=sysmlx --output=Spacecraft.sysmlx
msx sysml export Spacecraft.sysml --format=ssp --output=Spacecraft.ssp

# Import an OMG .sysmlx interchange file back into textual SysML v2
msx sysml import Spacecraft.sysmlx --output=Spacecraft.sysml

# Synchronize with Cameo Teamwork Cloud (TWC) or OpenMBEE MMS
msx sysml sync pull --target=twc --url=https://twc.example.com --resource=proj-123 --output=Model.sysml
```

## Programmatic Usage

```typescript
import { createWasmParser } from "@modelscript/sysml2/parser";
import { sysml2Language } from "@modelscript/sysml2/language";

// 1. Initialize WASM GLR parser
const wasmPath = require.resolve("@modelscript/sysml2/parser.wasm");
const { parser } = await createWasmParser(wasmPath);

// 2. Parse SysML v2 source
const tree = parser.parse(sourceText);

// 3. Inspect polyglot TGG rules for cross-domain compilation
const tggRules = sysml2Language.polyglot?.rules;
```
